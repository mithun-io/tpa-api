==================================================
POSTMAN TESTING GUIDELINES
==================================================
1. Authentication (Bearer Token): 
   Most endpoints require authentication. First, call `POST /api/v1/auth/login` to get your JWT access token.
   For protected endpoints, go to the "Authorization" tab in Postman, select "Bearer Token", and paste your token.
   Pay attention to the specific roles required for endpoints (e.g., FMG_ADMIN, CUSTOMER, CARRIER_USER, FMG_EMPLOYEE).

2. Path Variables ({id}, {claimId}, {email}):
   Replace the bracketed parts with real data in the URL.
   Example: `/api/v1/admin/users/{id}/block` becomes `/api/v1/admin/users/1/block`.

3. Query Parameters (?param=value):
   Add these in the "Params" tab in Postman or directly to the URL.
   Example: `/api/v1/admin/users?page=0&size=10`.

4. JSON Body:
   For POST, PUT, and PATCH requests, go to the "Body" tab, select "raw", and change the format from "Text" to "JSON".
   Copy the provided JSON payload examples and adjust values as needed.

5. File Uploads (Multipart Form-Data):
   For file upload endpoints, go to the "Body" tab, select "form-data".
   For normal text fields, keep the type as "Text". For file fields, hover over the key input, change the type to "File", and select your local file.
